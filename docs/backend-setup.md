# Local backend setup (no SST)

1. `bun install` at the repository root. Copy `.env.example` to the gitignored root `.env` and replace placeholders. The local default `.env` contains `DATABASE_URL=postgres://postgres:postgres@localhost:5431/postgres`. An isolated local Postgres 16 Docker container named `stockpile-local-postgres` is running on `127.0.0.1:5431` (created for local verification with default local credentials, no mounted volume). Check with `docker ps`; if stopped, `docker start stockpile-local-postgres`. Do not commit credentials.
2. The reviewed initial migration `drizzle/0000_last_khan.sql` was generated and applied to that **fresh local container only**. It creates tables without dropping or modifying existing data. For a different local database, first review its current schema and the SQL before applying `bun run db:migrate`; do not apply a baseline migration blindly to an existing database. To change the schema later, run `bun run db:generate`, review SQL, then apply only to the intended database.
3. Create a Privy app and set `PRIVY_APP_ID` / `PRIVY_APP_SECRET` in `.env`; send Privy **identity tokens** as `privy-id-token` on private requests. Privy verifies the identity token and provides authoritative linked accounts. A user wallet must be a verified Solana linked account, never a client-supplied address. Missing credentials disable private APIs; missing/invalid tokens fail closed.
4. Optional: set `HELIUS_API_KEY` for on-chain balances (SOL via `getBalance`, USDC and SPL / Token-2022 holdings via `getTokenAccountsByOwner`; xStocks are Token-2022). Without it, `/portfolio` explicitly returns `unavailable` with `sol`/`usdc` `null`. Set `JUPITER_API_KEY` for icons, live quotes, and swap preparation. Set `STOCKPILE_ALLOWED_MINTS=SYMBOL:SolanaMint,...` for **every** asset in a bag; a bag is `tradable` only when all its assets are listed, otherwise it stays discoverable but research-only. Never substitute ticker symbols for mints or copy unverified addresses. The eight starter mints in `.env.example` were verified on 2026-09-25 by (a) reading the issuer's paginated public directory `https://api.xstocks.fi/api/v2/public/assets` and taking each asset's `deployments[network=Solana].address`, and (b) confirming on Jupiter Tokens V2 (`/tokens/v2/search?query=<mint>`) that the exact id exists with the same symbol, 8 decimals, and `verified`/`xstocks` tags, and that `/swap/v1/quote` returns a USDC route. Re-verify before reusing on another deployment (`apps/api/src/lib/issuer-assets.ts` keeps the snapshot and a test asserts `.env.example` matches it). The eight PreStocks pre-IPO mints (`apps/api/src/lib/prestocks.ts`) were verified the same day by reading `https://prestocks.com/api/prestocks` (`contract_address`, all `Pre...`) and confirming on Jupiter the exact id, symbol, 9 decimals, `verified`+`prestocks` tags, and a live USDC route; the backend repeats the directory + Jupiter check at runtime (10 min / 1 h caches) and refuses any PreStocks mint the issuer no longer lists or Jupiter no longer verifies. Only PreStocks-issued tokens are used for pre-IPO exposure (Stocklana bounty rule). `STOCKPILE_PRESTOCKS=0` disables the directory. OPENAI and SPACEX use Token-2022 scaled UI amounts; the API exposes `uiAmountMultiplier` so clients can display wallet units. USDC mainnet is the only supported input. Jupiter `/swap/v1/quote` and `/swap/v1/swap` are used; routing is indicative; prepared transactions are unsigned v0 transactions whose fee payer the backend checks against the Privy-verified wallet; the user must review/sign/submit each leg, and the API never broadcasts or claims a fill. Trade failures are typed (`error.code`, see `docs/api-contract.md`).
5. User starts local API with `bun run api:dev` from the root (port 4040); agents should not start servers. `bun run generate:sdk` updates OpenAPI and the generated SDK without a running DB or SST. Set `EXPO_PUBLIC_API_URL` to the reachable API host on device; configure `CORS_ORIGINS` for browser origins if needed.

## Market data, price history, and Congress-disclosure bags

`apps/api/src/lib/market.ts` refreshes Jupiter Price v3 and Tokens v2 for every allowlisted mint in one batch (cached 60 s, stale-while-revalidate, refreshed by a background interval in `apps/api/index.ts`; request handlers only read the cache). Pyth Hermes (`Equity.US.<TICKER>/USD`) is used for the xStocks underlying price only when `PYTH_API_KEY` is set (Hermes returns 401 without one since the 2026-08-26 Pyth Core upgrade); otherwise Jupiter's xStocks stock reference (`stockData.price`) is used and labelled `jupiter-stock`. Token-2022 scaled-UI multipliers now come from the same snapshot for xStocks too (AAPLx/MSFTx/NVDAx/GOOGLx carry small dividend-adjustment multipliers; NFLXx is 10x after a split-style adjustment). `STOCKPILE_MARKET=0` disables market data.

`bun run prices:snapshot` writes one `price_snapshots` row per tracked mint (run hourly from a scheduler); `GET /bags/{id}/history` serves them. The reviewed additive migration `drizzle/0004_market_and_congress.sql` (creates `price_snapshots` and `congress_disclosures`) was applied to the isolated local container.

**Price charts (tokens.xyz).** `GET /assets/{mint}/chart`, `GET /bags/{id}/chart` and `GET /bags/sparklines` are served from tokens.xyz candles (`https://api.tokens.xyz/v1`, header `x-api-key`; `/assets/resolve?ref=<mint>` then `/assets/{assetId}/price-chart`), the same source riven-cash charts use. Set `TOKENS_API_KEY` in root `.env` locally; deployed stages read the `TokensApiKey` SST secret (`bunx sst secret set TokensApiKey <key> --stage <stage>`; it has an empty placeholder so deploys do not fail without it) which `infra/api.ts` passes to the Worker as `TOKENS_API_KEY`. Without a key the chart endpoints respond 200 with `points: []` and `reason: "unconfigured"` (never 500); `/bags/{id}/history` keeps its snapshot fallback. `bun run tokens:coverage` prints, per allowlisted mint, whether tokens.xyz resolves it and how far back daily candles go (needs the key; never prints it).

`bun run congress:ingest` reads STOCK Act periodic transaction reports for the eight tradable tickers from CongressInvests (`https://congressinvests.com/trades/{ticker}`, free tier: no key, 100 requests/day per IP, data refreshed every 6 h from House Clerk / Senate eFD; optional `STOCKPILE_CONGRESS_API_KEY` for the Pro tier). Rows are validated (official filing hosts only, parseable ranges, no future dates), upserted into `congress_disclosures`, and filings disclosed in the last 120 days become `format:"disclosure"` feed stories. The `pelosi-tracker` and `congress-consensus` bags are computed from that table at request time (cached 5 min). CongressInvests' terms: informational use only, no redistribution for commercial solicitation or advertising (House Clerk usage terms); Stockpile cites the official filing URL on every asset. QuantEngines (`/api/v1/trades/recent/list`) was also evaluated but returned an empty dataset on 2026-09-25.

## Curated news and podcast stories

The reviewed additive migrations `drizzle/0001_tense_iron_lad.sql` (creates `stories`) and `drizzle/0002_even_toad.sql` (adds `format` with an `article` default) were applied to the isolated local Postgres container, followed by `drizzle/0003_bags_rename.sql` (renames `saved_baskets`/`basket_id` to `saved_bags`/`bag_id`, recreates the PK/FK, and rewrites the `stories.connections` JSON key `basketId` to `bagId` in place; no rows dropped). On a different database, review the target and SQL before migrating. `drizzle-kit generate` prompts interactively for renames; the rename answer was chosen so the snapshot reflects a rename, not drop/create. Run `bun run stories:ingest` manually or from a trusted scheduler. It reads only fixed Microsoft, NVIDIA, Apple, Amazon, Google, and OpenAI publisher feeds, the TechCrunch AI, Ars Technica, CNBC Technology, Breaking Defense, and SpaceNews press feeds (keeping only items that explicitly mention a mapped company, e.g. OpenAI, Anthropic, Kalshi, Polymarket, SpaceX, Anduril for the PreStocks bags), and NVIDIA's identified show from Apple's podcast directory, stores at most five new items per source per run, and never refreshes them from a public request. No images are copied from article feeds: `imageUrl` and `imageCredit` are `null` for UI artwork fallback. Entries retain original publisher URLs, timestamps, and an editorial or AI provenance label.

`OPENAI_API_KEY` in the gitignored root `.env` optionally enables source-grounded AI curation on **new** items only; `STOCKPILE_AI_MODEL` defaults to `gpt-4o-mini`. Never put this API key in mobile environment variables. No key, provider failure, invalid structured output, or a detected prompt-injection phrase yields editorial/source-excerpt fallback. Already-ingested stories stay immutable; changing the AI key does not rewrite old summaries. Current seeded local stories are editorial because no OpenAI key was configured at ingestion time. `GET /stories?format=podcast` shows podcast episodes even when their authentic release dates put them after recent article stories.

Six starter bags (three xStocks, three PreStocks) are editorial interpretations of issuer product information; weights and thesis are not sourced claims, predictions, performance metrics, or recommendations. xStocks restrictions and issuer risk disclosures apply. `docs/api-contract.md` defines the integration interface. Existing SST deployment infrastructure may require separate adaptation to provide the new environment variables and remove obsolete Better Auth links; these local commands do not depend on SST.

For backend checks, `bun test apps/api` and `bunx tsc --noEmit -p apps/api/tsconfig.json` cover public responses, the allowlist/tradability rules, market snapshot caching/failure/premium/bag weighting, STOCK Act row parsing, tracker intersection/weighting and disclosure stories, transaction inspection, plus mocked authenticated account, Helius, and Jupiter flows (typed errors, per-leg labels, fee-payer checks). Run `bun --env-file=.env test tests/backend/database.integration.test.ts` and `bun --env-file=.env test tests/backend/story-feed.integration.test.ts` separately: Bun's module mocks are process-wide, so these isolated checks use real local Postgres with a mocked Privy identity, write isolated test rows, and remove them afterward. These tests do not certify live Privy credentials, live on-chain quotes, or actual wallet signing.
