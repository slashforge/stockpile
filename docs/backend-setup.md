# Local backend setup

All configuration is SST secrets (`infra/secrets.ts`) and the `AppConfig` linkable (`infra/config.ts`), read at runtime through `Resource.*` (API: `apps/api/src/lib/config.ts`; DB: `packages/core/db/index.ts`). There are no `.env` files for the backend. Set secrets per stage with `bunx sst secret set <Name> <value> [--stage <stage>]`, then run `sst dev` (links everything into the API `DevCommand`), or wrap one-off commands in `sst shell --` (the root `package.json` scripts already do).

| Secret | Required | Used for |
| --- | --- | --- |
| `DatabaseUrl` | yes | Postgres connection string. Deployed stages derive the Hyperdrive origin from it. |
| `PrivyAppId`, `PrivyAppSecret` | yes | Identity-token verification (private routes). `PrivyAppId` is also injected into Expo as `EXPO_PUBLIC_PRIVY_APP_ID`. |
| `PrivyClientId` | no | Privy mobile client id, injected into Expo as `EXPO_PUBLIC_PRIVY_CLIENT_ID`. Empty: browse-only app. |
| `JupiterApiKey` | yes | Icons, market data, token metadata, quotes, swap preparation. |
| `HeliusApiKey` | yes | Balances, activity, transaction simulation and relay. |
| `SolanaPaymasterKey` | no | SOL-funded fee payer for sponsored swaps. Empty: `/trade/prepare` returns `PROVIDER_NOT_CONFIGURED`. |
| `TokensApiKey` | no | tokens.xyz candles (charts, history). Empty: charts return `reason: "unconfigured"`. |
| `PythApiKey` | no | Pyth Hermes underlying prices. Empty: Jupiter stock reference. |
| `CongressApiKey` | no | CongressInvests Pro tier. Empty: free tier. |
| `OpenaiApiKey` | no | Offline story curation only. |
| `BlockedMints` | no | Emergency switch: comma-separated mints or symbols to stop trading (set, then redeploy). |

CORS origins come from `AppConfig.corsOrigins` (landing domain when deployed, localhost ports in local stages).

1. `bun install` at the repository root. Set `DatabaseUrl` to your local Postgres, e.g. `bunx sst secret set DatabaseUrl postgres://postgres:postgres@localhost:5431/postgres`. An isolated local Postgres 16 Docker container named `stockpile-local-postgres` is running on `127.0.0.1:5431` (created for local verification with default local credentials, no mounted volume). Check with `docker ps`; if stopped, `docker start stockpile-local-postgres`. Do not commit credentials.
2. The reviewed initial migration `drizzle/0000_last_khan.sql` was generated and applied to that **fresh local container only**. It creates tables without dropping or modifying existing data. For a different local database, first review its current schema and the SQL before applying `bun run db:migrate`; do not apply a baseline migration blindly to an existing database. To change the schema later, run `bun run db:generate`, review SQL, then apply only to the intended database.
3. Create a Privy app and set the `PrivyAppId` / `PrivyAppSecret` secrets; send Privy **identity tokens** as `privy-id-token` on private requests. Privy verifies the identity token and provides authoritative linked accounts. A user wallet must be a verified Solana linked account, never a client-supplied address. Missing credentials disable private APIs; missing/invalid tokens fail closed.
4. `HeliusApiKey` provides on-chain balances (SOL via `getBalance`, USDC and SPL / Token-2022 holdings via `getTokenAccountsByOwner`; xStocks are Token-2022). Without it, `/portfolio` explicitly returns `unavailable` with `sol`/`usdc` `null`. `JupiterApiKey` powers icons, live quotes, and swap preparation. Tradable mints need no configuration: each bag asset is resolved live from its issuer directory (xStocks per-symbol API, PreStocks directory), must match any mint pinned in `apps/api/src/lib/issuer-assets.ts`, and must pass Jupiter verification (exact mint, symbol, decimals, `verified` + issuer tag, live USDC route); a bag is `tradable` only when every asset resolves, otherwise it stays discoverable but research-only. The `BlockedMints` secret (comma-separated mints or symbols) switches a token off. OPENAI and SPACEX use Token-2022 scaled UI amounts; the API exposes `uiAmountMultiplier` so clients can display wallet units. USDC mainnet is the only supported input. Jupiter `/swap/v1/quote` (indicative quotes) and `/swap/v2/build` (prepare, RTSE slippage by default) are used. Set `SolanaPaymasterKey` to a dedicated SOL-funded wallet: it pays every swap's network fee and token-account rent and pre-signs as fee payer, so users never need SOL (see Prepare in `docs/api-contract.md` for the guards and spend caps). Keep it topped up (prepare refuses below 0.02 SOL). The user signs and submits each leg; the API never broadcasts or claims a fill. Trade failures are typed (`error.code`, see `docs/api-contract.md`).
5. User starts the stack with `sst dev` (API on port 4040; `bun run api:dev` runs just the API under `sst shell`); agents should not start servers. `bun run generate:sdk` updates OpenAPI and the generated SDK without a running DB or SST. For a physical device, start `sst dev` with `EXPO_PUBLIC_API_URL=http://<LAN-IP>:4040` in the shell so the Expo dev command picks it up.

## Market data, price history, and Congress-disclosure bags

`apps/api/src/lib/market.ts` refreshes Jupiter Price v3 and Tokens v2 for every known bag mint in one batch (cached 60 s, stale-while-revalidate, refreshed by a background interval in `apps/api/index.ts`; request handlers only read the cache). Pyth Hermes (`Equity.US.<TICKER>/USD`) is used for the xStocks underlying price only when the `PythApiKey` secret is set (Hermes returns 401 without one since the 2026-08-26 Pyth Core upgrade); otherwise Jupiter's xStocks stock reference (`stockData.price`) is used and labelled `jupiter-stock`. Token-2022 scaled-UI multipliers now come from the same snapshot for xStocks too (AAPLx/MSFTx/NVDAx/GOOGLx carry small dividend-adjustment multipliers; NFLXx is 10x after a split-style adjustment).

`bun run prices:snapshot` writes one `price_snapshots` row per tracked mint (run hourly from a scheduler); `GET /bags/{id}/history` serves them. The reviewed additive migration `drizzle/0004_market_and_congress.sql` (creates `price_snapshots` and `congress_disclosures`) was applied to the isolated local container.

**Price charts (tokens.xyz).** `GET /assets/{mint}/chart`, `GET /bags/{id}/chart` and `GET /bags/sparklines` are served from tokens.xyz candles (`https://api.tokens.xyz/v1`, header `x-api-key`; `/assets/resolve?ref=<mint>` then `/assets/{assetId}/price-chart`), the same source riven-cash charts use. Set the `TokensApiKey` secret (`bunx sst secret set TokensApiKey <key> [--stage <stage>]`; it has an empty placeholder so deploys do not fail without it). Without a key the chart endpoints respond 200 with `points: []` and `reason: "unconfigured"` (never 500); `/bags/{id}/history` keeps its snapshot fallback. `bun run tokens:coverage` prints, per known bag mint, whether tokens.xyz resolves it and how far back daily candles go (needs the key; never prints it).

`bun run congress:ingest` reads STOCK Act periodic transaction reports for the eight tradable tickers from CongressInvests (`https://congressinvests.com/trades/{ticker}`, free tier: no key, 100 requests/day per IP, data refreshed every 6 h from House Clerk / Senate eFD; optional `CongressApiKey` secret for the Pro tier). Rows are validated (official filing hosts only, parseable ranges, no future dates), upserted into `congress_disclosures`, and filings disclosed in the last 120 days become `format:"disclosure"` feed stories. The `pelosi-tracker` and `congress-consensus` bags are computed from that table at request time (cached 5 min). CongressInvests' terms: informational use only, no redistribution for commercial solicitation or advertising (House Clerk usage terms); Stockpile cites the official filing URL on every asset. QuantEngines (`/api/v1/trades/recent/list`) was also evaluated but returned an empty dataset on 2026-09-25.

## Curated news and podcast stories

The reviewed additive migrations `drizzle/0001_tense_iron_lad.sql` (creates `stories`) and `drizzle/0002_even_toad.sql` (adds `format` with an `article` default) were applied to the isolated local Postgres container, followed by `drizzle/0003_bags_rename.sql` (renames `saved_baskets`/`basket_id` to `saved_bags`/`bag_id`, recreates the PK/FK, and rewrites the `stories.connections` JSON key `basketId` to `bagId` in place; no rows dropped). On a different database, review the target and SQL before migrating. `drizzle-kit generate` prompts interactively for renames; the rename answer was chosen so the snapshot reflects a rename, not drop/create. Run `bun run stories:ingest` manually or from a trusted scheduler. It reads only fixed Microsoft, NVIDIA, Apple, Amazon, Google, and OpenAI publisher feeds, the TechCrunch AI, Ars Technica, CNBC Technology, Breaking Defense, and SpaceNews press feeds (keeping only items that explicitly mention a mapped company, e.g. OpenAI, Anthropic, Kalshi, Polymarket, SpaceX, Anduril for the PreStocks bags), and NVIDIA's identified show from Apple's podcast directory, stores at most five new items per source per run, and never refreshes them from a public request. No images are copied from article feeds: `imageUrl` and `imageCredit` are `null` for UI artwork fallback. Entries retain original publisher URLs, timestamps, and an editorial or AI provenance label.

The `OpenaiApiKey` secret optionally enables source-grounded AI curation (`gpt-4o-mini`) on **new** items only. It is never linked to mobile. No key, provider failure, invalid structured output, or a detected prompt-injection phrase yields editorial/source-excerpt fallback. Already-ingested stories stay immutable; changing the AI key does not rewrite old summaries. Current seeded local stories are editorial because no OpenAI key was configured at ingestion time. `GET /stories?format=podcast` shows podcast episodes even when their authentic release dates put them after recent article stories.

Ten starter bags (seven xStocks, three PreStocks) are editorial interpretations of issuer product information; weights and thesis are not sourced claims, predictions, performance metrics, or recommendations. xStocks restrictions and issuer risk disclosures apply. `docs/api-contract.md` defines the integration interface.

For backend checks, `bun test apps/api` and `bunx tsc --noEmit -p apps/api/tsconfig.json` cover public responses, live mint resolution / pins / blocklist and tradability rules, market snapshot caching/failure/premium/bag weighting, STOCK Act row parsing, tracker intersection/weighting and disclosure stories, transaction inspection, plus mocked authenticated account, Helius, and Jupiter flows (typed errors, per-leg labels, fee-payer checks). Run `bunx sst shell -- bun test tests/backend/database.integration.test.ts` and `bunx sst shell -- bun test tests/backend/story-feed.integration.test.ts` separately: Bun's module mocks are process-wide, so these isolated checks use real local Postgres with a mocked Privy identity, write isolated test rows, and remove them afterward. These tests do not certify live Privy credentials, live on-chain quotes, or actual wallet signing.
